# Poopify — инструкция по запуску и публикации

Poopify — адаптивный веб-сайт с анимированным кремово-жёлтым интерфейсом. Он работает как PWA: на телефоне можно добавить его на главный экран. Для общей ленты друзей используется Supabase, сайт размещается на Vercel.

## Важно знать до публикации

- **Без настроенного Supabase сайт запускается в демо-режиме** с примерами; добавленные записи остаются только в текущей вкладке/устройстве.
- SQL в `supabase/schema.sql` — стартовый вариант **публичной ленты без аккаунтов**: посетители могут читать записи и добавлять новые. Код комнаты — фильтр, а не пароль: он не защищает приватность.
- Не публикуйте настоящее имя, контакты, точное местоположение или реальные медицинские сведения. Если нужны настоящие приватные комнаты, сначала добавьте Supabase Auth и политики RLS, проверяющие членство пользователя в комнате.
- Никогда не вставляйте `service_role` / secret key в Vite-приложение. В браузере допустим только publishable key (старое название — anon key) при правильно настроенных RLS.
- Это первый MVP. Реакции/лайки пока локальные в браузере; в облако записываются ник, тип, объём, заметка, код комнаты и время.

## Что понадобится

1. Учётная запись GitHub: https://github.com
2. Учётная запись Vercel: https://vercel.com
3. Учётная запись Supabase: https://supabase.com
4. Компьютер. На телефоне можно создать проекты в сервисах, но подготовить код удобнее с компьютера.

## Часть 1. Создать базу данных в Supabase

1. Откройте https://supabase.com и зарегистрируйтесь.
2. Создайте новый проект (**New project**), назовите его `poopify`. Выберите регион рядом с основной аудиторией (например, EU, если друзья в Европе), задайте надёжный пароль базы и сохраните его в менеджере паролей.
3. Дождитесь, пока проект создастся.
4. В меню проекта откройте **SQL Editor** → **New query**.
5. На компьютере откройте файл `supabase/schema.sql` из этого архива, скопируйте весь текст, вставьте его в SQL Editor и нажмите **Run**.
6. Убедитесь, что запрос завершился без ошибок. В **Table Editor** должна появиться таблица `poop_entries`.
7. Если Realtime не включился автоматически: откройте **Database → Publications** (название пункта может немного отличаться), найдите публикацию `supabase_realtime` и включите для `poop_entries` события изменений. Для первой проверки достаточно обычного обновления страницы, даже если Realtime не настроен.

### Найти URL и ключ Supabase

1. В панели Supabase откройте **Connect** или **Project Settings → API** (интерфейс может отличаться).
2. Скопируйте **Project URL**.
3. Скопируйте **Publishable key**. Если интерфейс показывает старый ключ `anon`, он подходит для этого шаблона. **Не копируйте `service_role` или `secret` key.**
4. Эти два значения нужны на следующем этапе.

## Часть 2. Загрузить код на GitHub

### Вариант A — через сайт GitHub (без командной строки)

1. Распакуйте архив `poopify.zip` на компьютере.
2. Откройте https://github.com и нажмите **New repository**.
3. Назовите репозиторий `poopify`, выберите **Private** или **Public** и создайте его. (Private удобнее, если не хотите открывать исходный код.)
4. На странице пустого репозитория нажмите **Add file → Upload files**.
5. Перетащите **содержимое папки** `poopify` (файлы и папки `src`, `public`, `supabase`), а не сам zip-файл. Проверьте, что `package.json` находится в корне репозитория.
6. Нажмите **Commit changes**.

Не загружайте `.env.local` или секретные ключи в GitHub. В этом архиве есть только `.env.example` с фиктивными значениями.

## Часть 3. Опубликовать сайт на Vercel

1. Откройте https://vercel.com и войдите через GitHub.
2. Нажмите **Add New… → Project**.
3. Выберите GitHub-репозиторий `poopify` и нажмите **Import**.
4. Vercel обычно автоматически распознаёт Vite. Проверьте настройки:
   - Framework Preset: **Vite**
   - Build Command: `npm run build`
   - Output Directory: `dist`
   - Install Command: `npm install`
5. До первого деплоя можно сразу добавить переменные окружения в разделе **Environment Variables**:
   - `VITE_SUPABASE_URL` = Project URL из Supabase
   - `VITE_SUPABASE_PUBLISHABLE_KEY` = Publishable key (или старый anon key)
   Отметьте **Production**, а для удобства также **Preview** и **Development**, если такие варианты показываются.
6. Нажмите **Deploy**. Дождитесь окончания сборки.
7. Vercel выдаст адрес вида `https://poopify-....vercel.app`. Откройте его — это ссылка для друзей.
8. Если вы добавили/изменили переменные уже после публикации, откройте **Deployments** и сделайте **Redeploy**: новые значения не всегда применяются к уже собранной версии.

Официальная инструкция Vercel: https://vercel.com/docs/frameworks/frontend/vite

## Часть 4. Как сайт связан с базой

Связка работает так:

1. Браузер загружает приложение с Vercel.
2. Vite-приложение читает `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`.
3. Клиент Supabase подключается к облачному API проекта.
4. При добавлении записи приложение отправляет `INSERT` в `poop_entries`.
5. При открытии ленты приложение читает записи из таблицы, отфильтрованные по `room_code`.
6. Если включён Realtime, новые записи могут появляться у других посетителей почти сразу; иначе обновите ленту кнопкой со стрелками.

Vercel размещает **фронтенд**, а Supabase хранит **данные и базу**. Это два отдельных сервиса; приложение связывает их через URL и publishable key. Саму базу не нужно загружать в Vercel.

## Часть 5. Проверить, что всё работает

1. Откройте опубликованный сайт.
2. В верхней панели вместо «Демо-режим» должно быть «Облако подключено».
3. Введите ник, выберите тип/объём и нажмите «Зафиксировать покак».
4. Откройте Supabase → **Table Editor → poop_entries**. Новая строка должна появиться в таблице.
5. Откройте ссылку сайта в другом браузере/на телефоне, введите тот же код комнаты и проверьте, появилась ли запись.
6. Чтобы проверить комнаты, создайте запись в `KAKA-CLUB`, затем переключитесь на другой код через «Моя комната». В текущем MVP записи фильтруются по коду, но **не являются приватными**.

## Часть 6. Установить на телефон

### Android (Chrome)
1. Откройте сайт в Chrome.
2. Нажмите меню `⋮`.
3. Выберите **Установить приложение** или **Добавить на главный экран**.

### iPhone (Safari)
1. Откройте сайт в Safari.
2. Нажмите кнопку «Поделиться».
3. Выберите **На экран Домой**.

Это PWA-основа. Для полноценной офлайн-работы, push-уведомлений и более полного набора иконок потребуется дополнительная настройка.

## Если что-то не работает

- **Показывается «Демо-режим»** — переменные окружения отсутствуют/неверны. Проверьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` в Vercel → Settings → Environment Variables и сделайте Redeploy.
- **`Invalid API key`** — скопируйте publishable/anon key без пробелов; не используйте secret/service_role.
- **`relation poop_entries does not exist`** — SQL-схема не была выполнена в нужном проекте Supabase.
- **`permission denied` / ошибка RLS** — проверьте, что запускали `supabase/schema.sql` в том же проекте; не отключайте RLS для обхода ошибки.
- **Записи не обновляются мгновенно** — включите таблицу в публикацию `supabase_realtime`; ручное обновление должно работать и без Realtime.
- **Vercel не собирает проект** — убедитесь, что `package.json` и `src/` лежат в корне репозитория, а не во вложенной папке.
